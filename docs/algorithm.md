# 羁绊天梯 / 拼盘天梯：递推与损失

状态为 `(L, C, E)`：人口等级 L、冠冕数量 C、卡兹克进化次数 E。阵容栏位为 `L+C`，商店按 L 级概率计算。冠冕范围 0–3，进化次数范围 0–4。

## 三维递推

每个状态保存各羁绊数量的候选阵容，以及沿选中方案已收集的角色集合 A。前置状态为：

```text
(L-1, C, E)
(L, C-1, E)
(L, C, E-1)
```

只使用坐标有效的前置状态。令 H 为这些前置状态的 A 的并集，O 为用户勾选的已有角色。当前状态求解完成后：

```text
H[L,C,E] = 并集 A[各有效前置状态]
S[L,C,E] = 用户点选的方案；未点选或点选无效时，取 orderings.value 第一项
A[L,C,E] = H[L,C,E] ∪ S[L,C,E].board
```

获取成本按以下约定计算：O 和 H 中的角色成本为 0，其他角色按当前商店计算。每个前置状态只贡献选中方案的 board 及其更早已收集集合。未选中方案即使已展示，也不会成为零成本来源；置灰方案仅在被选中时贡献其 board。没有可行方案时只传递 H。用户的实际已有标记独立保存。

展示用的候选集合 B 为前置 B 与当前所有候选 board 的并集（含置灰候选），返回为 `candidate_units`，只用于侧栏“本局卡池”。继承使用 `acquired_units`，两者互不替代。

卡兹克确认进化的职业按确认顺序记录。较低次数的前置状态使用对应的记录前缀，当前次数保留已确认职业，再联合优化新增职业。各状态的阵容可自由重组。点击已确认的羁绊图标会从固定职业集合中删除该项，将进化次数 E 减 1，并触发矩阵重新计算。

计算结果只取决于本次请求的输入、实际持有和点选，与此前计算和持有标记顺序无关。始终使用 `A = H ∪ S.board`，不并入以前计算的历史牌集。取消持有后，只有本次前驱选中路径仍包含该牌时才会继承为零成本；否则按当前商店概率计算。

网页按当前输入和持有缓存已完成的格子；这些条件变化时重建派生矩阵，不从旧缓存迁移牌集。Python API 仅在同一请求内复用格子。点选按完整 `L,C,E` 坐标独立保存。改变点选时，复用当前格候选并更新 A，只让坐标逐维不小于该格、且不等于该格的严格后继缓存失效。切换显示排序不产生点选，也不改变默认选中方案。

API 和网页仍接受旧格式 `memory`，但忽略其内容，不用于继承、成本、默认选择或恢复点选。响应中的 `memory` 仅为当前已访问格子的快照，保留 `scope`、`owned`、`selections` 和 `states[].cards` 格式供检查；`inheritance: selected-plan-v1` 标记保持兼容。每次请求需通过独立 `selections` 传入有效点选。网页独立保存实际持有、点选和展示用的 `gamePool`；本局卡池可保留以前出现的候选，但不会自动成为继承来源。重置会清空这些本局设置与快照。

## 单卡获取成本

对每张需要新增获取的卡 i，设费用概率为 o，剩余张数为 r，同费完整卡池剩余总数为 R：

```text
p[i] = o[L,费用] × r[i] / R[费用]
q[i] ≈ 1 - (1-p[i])^5

d[i] = 0                         当 i 属于 O ∪ H
       1/q[i]                    当 q[i] > 0
       正无穷                    当 q[i] = 0 且 i 属于待获取卡
```

实际已有卡和额外离池张数用于更新卡池分母。递推得到的 H 用于成本记忆。拉克丝形态共享一个英雄池；未拥有形态的分布按均匀模型计算。静态卡池和独立商店格是计算假设。

## 每个羁绊数量的方案

每个格子先求可达到的羁绊上限，再对各数量 K 分别求解二元整数规划：

```text
x[i] = 弈子是否登场
y[t] = 羁绊是否激活
z[t] = 是否选择该项新增进化

Σ 弈子人口消耗 × x[i] = L+C
Σ y[t] = K
Σ z[t] = E - 已固定进化数量
第一目标：最小化 D = Σ d[i] × x[i]
第二目标：在 D 保持最优时，最大化实际已持有弈子的登场数量
第三目标：按弈子编号升序逐位优先登场，再按职业目录的固定顺序逐位优先选择
```

羁绊贡献为 `N[t]=Σ a[i,t]x[i]+纹章枚数+进化贡献`。门槛 b 与激活变量通过两条约束保持等价：

```text
N[t] >= b[t] × y[t]
N[t] <= b[t]-1 + M[t] × y[t]
```

模型同时处理同名和形态互斥、宿敌互斥、远古巨龙的双人口、拉克丝的双计数。进化次数大于 0 时卡兹克强制登场，并按已拥有计价。同角色贡献、人口消耗相同且获取成本更低的互斥选项用于裁剪；已有状态与继承状态参与这个比较。

网页和 API 的默认候选从 2 羁绊开始；较低等级未达到 2 时保留已达到的上限。`minimum_traits` 可指定较低基线，CLI 包含 0、1 羁绊基线。具体 `trait_counts` 作为返回视图筛选，前置格子仍按统一候选范围递推。

最优性证明针对每格给定继承集合下的搜卡目标。最低成本确定后，按已持有数量和固定编号顺序继续求解。编号对应的二元变量每 16 位组成一段，段内权重为 2 的幂；已持有数量的优先权重大于该段全部权重之和。每段证明最优后固定该段，再求下一段，由此得到完整的字典序。职业目录采用赛季资料中的固定顺序；界面各处统一先列羁绊、再列职业。Python 与网页采用相同次序。API 的 `canonical_status` 表示最终排序的证明状态。

Python 使用 `scipy.optimize.milp`（底层 HiGHS），网页使用 highs-js 1.15.4 内的 HiGHS 1.15.1 WebAssembly。网页将同一二元模型转换为 CPLEX LP 文本，羁绊上限、最低成本、持有优先和逐段排序全部由 HiGHS 求解；相对与绝对 MIP gap 均设为 0。每次阵容求解的全部阶段共用 8 秒，使用单调时钟 `performance.now()` 扣除已用时间，再通过 `time_limit` 传入剩余秒数。只有 HiGHS 的 `Optimal` 状态才作为最优证明；时间限制终止记为 `limit`，`Infeasible` 记为无解。

同一 K 的阵容因此具有确定顺序。跨 K 的默认选择使用下面的“损失 ↑”排序函数。API 的 `inherited_units`、`acquired_units`、`selected_trait_count`、`selection_status`、`predecessors` 和 `states` 保存递推依据。`trait_counts` 只筛选返回视图，不改变该格用于继承的选择。

## 损失与排序

```text
损失 D = Σ d_i = 阵容中各张待补弈子平均需要等待的商店次数之和
单位：次商店
```

损失现在等于 D（`difficulty`），单位为次商店，无需补牌时为 0。页面直接显示损失，保留一位小数，D=0 显示 0。“损失 ↑”依次比较 D（按 1e-7 次商店取整，正数半步向上）升序、羁绊数降序。这个精度对应旧损失排序的 1e-9 精度。跨羁绊数不比较持有数量。同一羁绊数内，求解器在获取成本相同时优先使用更多实际持有牌，继承牌不算实际持有；进化卡兹克及拉克丝的持有判定沿用已有规则。显示和未点选状态的默认继承使用同一排序函数。“羁绊 ↓”按羁绊数降序，同羁绊数按 D 升序。

Python 与 JS 方案只输出 D；删除 `loss`、`loss_lower_bound`、`value_score` / `value`、`value_upper_bound`。Python 保留 `difficulty_lower_bound`，主目标的证明状态统一为 `difficulty_status` / `difficultyStatus`。固定分界为 `difficulty_boundary` / `difficultyBoundary`。API 排序模式 `value` 作为已有请求及持久化选择的兼容键保留，含义为损失升序；它不代表评分字段。

## 统一损失分界

所有状态共用 [data/loss-reference.json](../data/loss-reference.json) 中的固定 D 分界。文件名及 `scripts/calibrate_loss.py` 保留以维持已有命令和引用；内容明确记录 `metric: difficulty`、`unit: shops`。

基准仍为标准卡池、无纹章、未持有卡的完整三维矩阵：人口等级 1–10、冠冕 0–3、进化次数 0–4，共 200 个状态。取其中 K 为 2–14、D>0 的 1062 个方案作为标定样本。

仍在原评分坐标标定，绝不在 log(D) 上重拟合：

```text
V = 100/(1+D)
x = log(V)
SSE(k) = Σ低组(x-μ低)² + Σ高组(x-μ高)²
τ_V = exp((μ低+μ高)/2)
τ_D = 100/τ_V - 1
```

`fit_value_boundary` / `fitValueBoundary` 从 D 临时计算 V 并执行原有对数方差标定；`fit_difficulty_boundary` / `fitDifficultyBoundary` 将结果转换到 D。与旧损失分界 τ 的关系为 τ_D = 100·τ − 1，旧 τ=0.17562403122788517 对应 D=16.562403122788517。v5 保持相同样本、分组和 SSE。`lower_center` / `higher_center` 是原坐标几何组中心转换到 D 后的值，并非 D 的几何平均数。

当前版本为 `s18-standard-matrix-v5`。当前候选数量、持有标记和局内缺卡变化均保持该标准。以未舍入的 D 判断：D>τ_D 时方案行置灰、数字标红，等于阈值时不置灰；显示为一位小数的 16.6。候选角色仍参与展示集合，仅在方案选中时参与已收集集合。

更新数据快照时可运行 `python scripts/calibrate_loss.py` 重新标定；网页只读取已发布基准。

## 验证

小棋池用独立穷举核对每个状态、每个 K 的最低新增成本。矩阵回归检查三个前置方向选中路径的并集、未选中牌不继承、点选变更与无效点选回退、不同羁绊数同损失时更多羁绊优先、同一羁绊数同成本时实际持有优先、继承卡零成本、已有标记和卡池分母、禁止未来状态回流，以及缓存复用。`scripts/verify_values.py` 用新递推重建全部转职、1–10 级的对照数据；网页逐状态核对全部候选、成本、阵容、继承集合和排序。
