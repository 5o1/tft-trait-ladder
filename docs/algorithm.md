# 羁绊天梯 / 拼盘天梯：递推与损失

状态为 `(L, C, E)`：人口等级 L、冠冕数量 C、卡兹克进化次数 E。阵容栏位为 `L+C`，商店按 L 级概率计算。冠冕范围 0–3，进化次数范围 0–4。

## 三维递推

每个状态保存各羁绊数量的候选阵容，以及累计出现过的角色集合 A。前置状态为：

```text
(L-1, C, E)
(L, C-1, E)
(L, C, E-1)
```

只使用坐标有效的前置状态。令 H 为这些前置状态的 A 的并集，O 为用户勾选的已有角色。当前状态求解完成后：

```text
H[L,C,E] = 并集 A[各有效前置状态]
A[L,C,E] = H[L,C,E] ∪ 当前所有候选阵容中的角色
```

获取成本按以下约定计算：O 和 H 中的角色成本为 0，其他角色按当前商店计算。累计集合汇总前置状态全部返回的候选，包括置灰候选。用户的实际已有标记独立保存。

卡兹克确认进化的职业按确认顺序记录。较低次数的前置状态使用对应的记录前缀，当前次数保留已确认职业，再联合优化新增职业。各状态的阵容可自由重组。点击已确认的羁绊图标会从固定职业集合中删除该项，将进化次数 E 减 1，并触发矩阵重新计算。

网页按需展开目标状态的前置矩阵，并缓存已完成的格子。切换持有状态时重新优化，并保留其它英雄的获取记录。取消持有会清除该英雄及其各形态的历史获取来源，再按商店概率重新计算该英雄的成本。历史记录中的弈子须能在对应状态或其前置状态的商店中获得，或具有当前持有、已进化卡兹克等来源。禁卡表、转职、已确认进化或形态约束变化时，重建对应的派生矩阵。矩阵记忆随本局设置保存在浏览器中，重置后清空。

## 单卡获取成本

对每张需要新增获取的卡 i，设费用概率为 o，剩余张数为 r，同费完整卡池剩余总数为 R：

```text
p[i] = o[L,费用] × r[i] / R[费用]
q[i] ≈ 1 - (1-p[i])^5

d[i] = 0                         当 i 属于 O ∪ H
       1/q[i]                    当 q[i] > 0
       正无穷                    当 q[i] = 0 且 i 属于待获取卡
```

实际已有卡和额外离池张数用于更新卡池分母。递推得到的 H 用于成本记忆。拉克丝形态共享一个英雄池；未拥有形态的分布按均匀模型计算。静态卡池和独立商店格是计算假设。

## 每个羁绊数量的方案

每个格子先求可达到的羁绊上限，再对各数量 K 分别求解二元整数规划：

```text
x[i] = 弈子是否登场
y[t] = 羁绊是否激活
z[t] = 是否选择该项新增进化

Σ 弈子人口消耗 × x[i] = L+C
Σ y[t] = K
Σ z[t] = E - 已固定进化数量
第一目标：最小化 D = Σ d[i] × x[i]
第二目标：在 D 保持最优时，最大化实际已持有弈子的登场数量
第三目标：按弈子编号升序逐位优先登场，再按职业目录的固定顺序逐位优先选择
```

羁绊贡献为 `N[t]=Σ a[i,t]x[i]+纹章枚数+进化贡献`。门槛 b 与激活变量通过两条约束保持等价：

```text
N[t] >= b[t] × y[t]
N[t] <= b[t]-1 + M[t] × y[t]
```

模型同时处理同名和形态互斥、宿敌互斥、远古巨龙的双人口、拉克丝的双计数。进化次数大于 0 时卡兹克强制登场，并按已拥有计价。同角色贡献、人口消耗相同且获取成本更低的互斥选项用于裁剪；已有状态与继承状态参与这个比较。

网页和 API 的默认候选从 2 羁绊开始；较低等级未达到 2 时保留已达到的上限。`minimum_traits` 可指定较低基线，CLI 包含 0、1 羁绊基线。具体 `trait_counts` 作为返回视图筛选，前置格子仍按统一候选范围递推。

最优性证明针对每格给定继承集合下的搜卡目标。最低成本确定后，按已持有数量和固定编号顺序继续求解。编号对应的二元变量每 16 位组成一段，段内权重为 2 的幂；已持有数量的优先权重大于该段全部权重之和。每段证明最优后固定该段，再求下一段，由此得到完整的字典序。职业目录采用赛季资料中的固定顺序；界面各处统一先列羁绊、再列职业。Python 与网页采用相同次序。API 的 `canonical_status` 表示最终排序的证明状态。

同一状态中的阵容因此具有确定顺序；后续继承以按该顺序选出的角色集合为依据。API 的 `inherited_units`、`acquired_units`、`predecessors` 和 `states` 保存递推依据。

## 损失与排序

```text
D = 新增获取成本之和
原评分 V = 100/(1+D)
损失 ℓ = 1/V = (1+D)/100
```

损失越小越优先，同损失时优先更多羁绊。另一种排序按羁绊数量降序。成本为 0 的方案损失为 0.01。

D 是单卡等待次数的加性指标；整套阵容的补卡过程可能在同一商店取得多张卡。损失用于当前递推规则下的跨状态比较，数值尺度始终一致。例如 D=10 时，任何状态的损失均为 0.11。原始 `value_score` 字段保留在计算结果中，页面展示 `loss`。

## 统一损失分界

所有状态共用 [data/loss-reference.json](../data/loss-reference.json) 中的固定分界。损失由统一公式计算，同一数值在各人口、冠冕、进化及持有状态下使用相同的标色标准。

基准取标准卡池、无纹章、未持有卡的完整三维矩阵：人口等级 1–10、冠冕 0–3、进化次数 0–4，共 200 个状态。取其中 K 为 2–14、需要新增获取的方案作为标定样本。零获取成本方案的损失固定为 0.01。

对基准损失取对数，枚举切分并最小化两类内部方差：

```text
x = log(损失)
SSE(k) = Σ低组(x-μ低)² + Σ高组(x-μ高)²
统一损失阈值 τ = exp((μ低+μ高)/2)
```

当前基准采用固定完整排序，含 83 个正成本样本，分界为 0.2234507660，版本为 `s18-standard-matrix-v2`。这个值随基准版本保存，当前候选数量、持有标记和局内缺卡变化均保持该标准。高于分界的方案置灰并将损失数字标红；角色仍参与累计集合。

分界定义的是相对于固定标准矩阵的高低成本类别。具体对局的经济预算仍是另一项信息。`scripts/calibrate_loss.py` 用于更新数据版本时重新标定，网页计算直接读取已经发布的基准。

## 验证

小棋池用独立穷举核对每个状态、每个 K 的最低新增成本。矩阵回归检查三个前置方向的并集、继承卡零成本、已有标记和卡池分母、禁止未来状态回流，以及缓存复用。单状态内核继续使用历史完整棋池记录进行 Python 与 JavaScript 对照。
